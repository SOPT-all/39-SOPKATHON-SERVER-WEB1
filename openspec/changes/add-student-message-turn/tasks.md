# Tasks

## 1. 이야기 기록 조회와 턴 저장

- [x] 1.1 이야기별 최신 메시지 ID와 장면 생성 입력 조회를 구현한다. 진행 11턴 사이에 교정 턴이 있는 데이터에서 최근 진행 10쌍, 현재 인물 상태, 첫 턴의 사건을 포함한 해당 이야기의 모든 사건이 전달되는지 확인한다. 첫 발화·두 번째 진행·10/11턴 경계에서 전송 본문의 시작 장면 포함 여부를 확인한다.
- [x] 1.2 학생 원문과 답변을 함께 저장하고, 진행 결과에 따라 인물 현황 한 건을 생성·갱신하고 새 사건들을 추가한다. 변화 없음·첫 변화·재갱신 및 저장 실패 시 전체 롤백을 영속성 테스트로 확인한다.

## 2. 교정과 장면 생성

- [x] 2.1 서버에 OpenAI 연결 설정과 두 모델을 구성하고 필요한 환경 설정을 실행 문서에 적는다. 테스트 환경은 실제 키 없이 대역으로 두 모델 요청을 구분할 수 있어야 한다.
- [x] 2.2 두 호출에 지침을 주입할 수 있게 하고 구조화된 결과를 검증한다. 교정 분기는 동시에 시작한 장면을 기다리지 않고 폐기하며, 통과 분기는 장면 생성 응답에서 장면·인물 현황·건별 사건을 읽는지 테스트한다. 타임아웃 및 불완전한 응답은 AI 처리 실패로 검증한다.
- [x] 2.3 합의한 교정 기본 프롬프트와 생성 토큰 상한을 적용하고, 권장 길이 초과 피드백의 저장 및 반환을 검증한다.
- [x] 2.4 장면 생성 프롬프트에 장면 진행, 인물·사건 갱신 기준과 50~120자 권장 길이를 적용한다.

## 3. 공개 전송 API

- [x] 3.1 이야기별 메모리 선점, 최신 ID 검증, 결과 저장과 선점 해제를 연결한다. 동시 요청 하나만 AI로 전달되고, 오래된 ID와 처리 중 충돌이 구분되며, 두 번째 호출 실패 후 저장 내역 없이 다시 전송할 수 있는지 확인한다.
- [x] 3.2 전송 엔드포인트에 요청 검증과 공통 응답을 적용한다. MVC 테스트로 공백·필수 값 누락·유니코드 코드 포인트 500/501 경계, 이야기 없음, 두 성공 결과의 메시지 순서와 ID, 409·503 응답을 확인한다.

## 4. 연동 검증

- [x] 4.1 실제 모델로 자연스러운 단답 통과·소지자 변경 후 기존 약속 유지·첫 장면 단서 회상을 확인한다. 교정 → 수정 후 진행 흐름과 오래된 은열쇠 사건을 간접적으로 언급하는 시연을 확인한다. 제안만 한 행동이 완료된 사건으로 기록되지 않는지, 성공 응답의 두 메시지가 저장된 내역과 일치하는지 확인한다.
- [x] 4.2 프로젝트 루트에서 `./gradlew clean build`로 전체 빌드와 테스트를 검증한다.

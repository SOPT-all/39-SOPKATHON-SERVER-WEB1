# Proposal

## Why

학생이 이야기의 마지막 장면을 읽고 문장을 보내면, 그 선택을 반영한 다음 장면이나 문장을 고쳐 볼 단서가 필요하다. 여러 학생이 같은 대화를 이어 쓰므로 한 장면에서 서로 다른 두 답변이 동시에 이어지는 일도 막아야 한다.

## What Changes

- 공개 API `POST /api/v1/stories/{storyId}/messages`를 추가한다. 입력 제약, 응답 필드와 오류 코드는 [6번 API 명세](https://app.notion.com/p/41f14af65e06812aba4bc3b79540d8bb)를 따른다.
- 명백한 맞춤법·어휘 오류에는 이유와 수정 예시를 담은 피드백을 반환한다. 자연스러운 짧은 답·생략형과 예상 밖의 행동은 허용한다. 교정된 문장으로 다시 보내면 해당 문장을 기준으로 진행 여부를 판단한다.
- 교정과 장면 생성을 병렬로 시작하고 교정 결과에 따라 저장한다. 교정 턴에는 학생 원문과 피드백만 저장한다. 진행 턴에는 세계관, 최근 진행 10턴, 현재 인물 상태, 같은 이야기의 사건 전체를 제공해 AI가 이번 장면에 필요한 사건을 골라 쓰게 하고 학생 원문·새 장면·그 안에서 성립한 인물 및 사건 변화를 함께 저장한다. [공유 이야기 채팅의 컨텍스트 설계](https://app.notion.com/p/41f14af65e06807289a9e923756ee503)
- 같은 이야기의 동시 전송은 한 요청만 선점할 수 있다. 처리 중인 턴과 이미 달라진 마지막 메시지를 구분하고, 충돌 또는 AI 실패 시 해당 전송의 메시지와 맥락 변경을 모두 저장하지 않는다.

## Impact

- 기존 세계관·채팅·맥락 엔티티와 공통 응답 형식을 사용한다. 채팅 내역 조회는 성공한 턴의 두 메시지를 원문, 답변 순서로 읽을 수 있어야 한다. [관련 이슈 #17](https://github.com/SOPT-all/39-SOPKATHON-SERVER-WEB1/issues/17)

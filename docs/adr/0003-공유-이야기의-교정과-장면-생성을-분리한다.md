# 공유 이야기의 교정과 장면 생성을 분리한다

## Context and Problem Statement

여러 학생이 한 이야기를 이어 쓰며, 교정 대상인 행동은 이야기에서 일어난 사실이 되어서는 안 된다. 단일 앱으로 시연하는 동안 AI 응답을 기다리면서 DB 연결이나 행 잠금을 점유하지 않아야 한다.

## Considered Options

- 교정과 진행을 한 번에 생성하면 진행 턴의 왕복 횟수가 줄어든다.
- 먼저 교정하고 통과한 경우에만 장면과 기억을 생성하면 두 결과의 품질을 독립적으로 검증할 수 있다.
- 과거 사건은 키워드·임베딩으로 선별하거나 같은 이야기의 기록 전체를 모델에 제공할 수 있다.

## Decision Outcome

진행 턴 대기를 줄이기 위해 교정과 장면·기억 생성을 병렬로 호출한다. 교정 통과 시에만 생성 결과를 반영한다. 인물 현황은 현재 사실로 갱신하고 중요한 사건은 건별로 누적한다. 최근 진행 10턴과 동일 이야기의 모든 사건을 전달해 간접적인 언급도 해석할 수 있게 한다. 상태를 쓰는 주체는 서버다. 이야기별로 처리 권한을 선점하고, 한 턴의 메시지와 기억을 함께 커밋한다.

### Consequences

- Good, because 교정으로 끝난 행동은 이후 장면의 사실로 섞이지 않는다.
- Bad, because 교정 턴에서도 폐기할 장면 생성에 비용이 발생할 수 있다.
- Good, because 사건 검색 인프라를 별도로 운영할 필요가 없다.
- Bad, because 이야기가 길어질수록 모델 입력도 커진다.
- 메모리 선점은 앱 한 대에서 유효하다. 여러 인스턴스가 같은 이야기에 쓰기 시작하면 DB 선점 방식을 재검토한다.
- 구체적인 입력 경계와 프롬프트 검증 예시는 [6번 API 변경 명세](../../openspec/changes/add-student-message-turn/specs/student-message-turn/spec.md)에 둔다.

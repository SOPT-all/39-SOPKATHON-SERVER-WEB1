# 서버 팀의 설계 결정을 MADR로 관리한다

## Context and Problem Statement

여러 팀원과 에이전트가 설계 선택을 재검토할 때 당시의 대안과 제약, 현재 유효한 결정을 같은 위치에서 찾을 수 있어야 한다.

## Considered Options

- 노션에서 결정과 대체 이력을 관리한다.
- 저장소에 MADR을 두고 adrs로 번호·상태·대체 관계를 관리한다.

## Decision Outcome

저장소에 MADR을 두는 방식을 제안한다. 코드와 결정 이유를 같은 PR에서 검토할 수 있고 CLI와 MCP가 동일한 원본을 조회한다.

### Consequences

- Good, because 팀원은 Git만으로 결정의 근거와 변경 이력을 읽을 수 있다.
- Bad, because 작성자는 adrs를 준비하고 대체하는 두 기록을 함께 검토해야 한다.
